# Files

- [Data Model & Storage, launcher.db v19, metadata.db, config.toml, and hybrid hosts](data-model.md) - SSHub persists each profile's state in two SQLite databases (launcher.db at schema v19 for managed hosts, groups and their connection defaults, identities, tunnels, audit, snippets, log bookmarks and opt-in command history; metadata.db for legacy ssh_config aliases), snapshots launcher.db before every migration, keeps settings in config.toml, and merges managed hosts with read-only ~/.ssh/config aliases through HostResolver.
- [Runtime Architecture, Event Loop, App State, and Source Map](overview.md) - How SSHub runs. main.rs dispatch, profile resolution, the synchronous 50 ms event loop in src/lib.rs driving the App state machine (40 AppMode variants plus a numeric active_tab), the ratatui render pipeline in src/tui, the mpsc background workers, and a module-by-module source map.
- [Profiles, isolated workspaces, startup picker, legacy migration, and cross-profile transfers](profiles.md) - How src/profile isolates each profile's databases, config.toml, fallback credentials, logs and tunnel state under profiles/<name>/, how startup picks a profile (silent, picker, --profile, compat mode), how the in-app manager switches profiles safely, how legacy installs migrate, and how the store transfer engine copies or moves entities between profiles.
- [Theme System Internals, registry, resolver, ThemeManager, and picker](themes.md) - How src/theme turns five embedded built-ins and user TOML files into one immutable ResolvedTheme owned by App (25 semantic slots, 234 component roles, static gradients), how the runtime falls back to default, how the theme picker previews and persists, and where the sshub theme CLI fits. The authoring guide is docs/theme-system.md.
